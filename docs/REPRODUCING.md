# Reproducing the focused study

## Run the supplied models

Install with Python 3.11 using the root README. Commands run from the repository root. `pyproject.toml` declares the tested NumPy, SciPy, Matplotlib, and PyTorch versions.

```bash
python -m electrolyte_surrogate.demo
python -m electrolyte_surrogate.evaluate
python -m unittest discover -s tests -v
```

The default demo generates four independent 100-time cases: step, pulse, reversal, and oscillating field. It writes `field_responses.png`, one prediction CSV per case, and `overview_metrics.json` to `runs/demo/`. Rows show the field/bare coefficient, electrostatic coefficient, and full hydrodynamic coefficient. These late-change examples are separate timing-transfer probes, not training records.

For a custom field, use a `tau,f` CSV with uniform spacing 0.05 and zero-field equilibrium initialization:

```bash
python -m electrolyte_surrogate.demo --input data/example_field.csv --output runs/custom-demo
```

Evaluation writes metrics over complete 100-time histories and separately over the 0–12 prefix, a long-step figure, switch-off with wrong-sign markers, signed predictions, physical tail scores, and matched warmed CPU timings to `results/reproduced/`. Timings use identical 2,001-sample inputs and exclude loading, training, and data generation. The committed `results/` files were generated by this package.

## Rebuild or refit

```bash
python -m electrolyte_surrogate.generate_data
python -m electrolyte_surrogate.train --model baseline
python -m electrolyte_surrogate.train --model gru
python -m electrolyte_surrogate.train --model physical
python -m electrolyte_surrogate.evaluate --artifacts runs/training
```

Data generation writes to `runs/generated_data/` using the recorded seed, early-change waveform recipe, and final holds through time 100. Fitting uses the supplied dataset by default; add `--data runs/generated_data/dataset.npz` to use regenerated labels. The archived labels were extended in blocks; a direct rebuild can differ at numerical-roundoff scale. Verification compares labels to a numerical tolerance rather than requiring identical compressed bytes.

Each fitting command independently writes its model to `runs/training/`: `baseline.npz`, `gru.pt`, or `covariance_weights.npz`. Evaluation requires all three. New GRU training writes `training_history.json`; the supplied history is in `artifacts/`.

The default GRU curriculum reproduces the recorded long-history recipe: seed 13, batch size 64, scaled MSE, gradient clipping at 1, and 120 warm-up epochs on the 0–12 prefix using Adam at 0.003 and a validation plateau scheduler (factor 0.5, patience 7). It then preserves optimizer and random-generator state for 20 epochs on full 0–100 histories at learning rate 0.0003. Output scales remain the training-prefix RMS. The final checkpoint is selected by complete 100-time validation with a 1e-4 improvement tolerance; the supplied fit selects continuation epoch 20. `--warmup-epochs` and `--epochs` control the two budgets. Short runs are useful for checking the workflow, not reproducing the reported accuracy.

Regression fits complete 100-time records with the same output scales. Validation selects among 20, 60, 120 lags and ridge factors 1e-5, 1e-3, 1e-1; the selected fit uses 120 lags and 1e-5. Features use past f and f³ for the electrostatic term, and past f² for the even hydrodynamic coefficient.

Physical fitting uses the selected 24-by-12 grid and ridge factor 1e-5. It minimizes relative transient errors with numerical floors, positivity bounds, and stationary equality constraints at 11 training amplitudes. Targets contain 122 log-spaced/zero observations through time 1,000 from a fine covariance grid. Four amplitudes provide validation; five separate amplitudes form the tail test. This command refits the selected configuration rather than repeating the exploratory grid search.

## Data, artifacts, and interpretation

`data/dataset.npz` contains `tau (2001,)`, `field (1088,2001)`, `target (1088,2001,2)`, and `split`/`family` arrays. Fields and targets are float32. Labels use reference quadrature orders 48/48. All histories span 0–100; whole histories define the splits. Training changes occur early, so this is not a dataset of arbitrary late-time switching.

`artifacts/` holds fitted coefficients, weights, normalization, settings, and training history. Lineage and hashes are in `provenance.json`. Tests cover independent physical solutions, stationary currents, on/off behavior, causality, parity, nonuniform physical histories, and exact reconstruction of all stored field/split recipes. [VERIFICATION.json](VERIFICATION.json) records training and label checks.

Ordinary NRMSE divides by RMS reference signal. The hydrodynamic metric uses `f*Y_hyd`, excluding the known `-f` baseline. Tail errors use departures from the true stationary value with a numerical floor. GRU inference is float32; physical calculations are float64. Pointwise relative errors near zero crossings or below a floor are not meaningful.

The long-step diagnostic extends beyond the GRU training horizon, while physical fitting covers that longer window. The f=3 step has informed the investigation repeatedly and is not a blind model-selection test. These are particular single-seed fits, not a theorem about neural memory.
